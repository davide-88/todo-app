## Successes

- **Velocity acceleration:** Stories 1.1-1.2 were rough with tooling friction; Stories 1.3-1.5 were progressively smoother as patterns compounded
- **`useTodoStates` hook reusability:** Designed in Story 1.4 for create mutations, slotted into toggle and delete (Story 1.5) with zero modifications
- **`TodoRepository` interface:** Made unit testing routes trivially simple — just `vi.fn()` per method, no Drizzle chain mocking
- **Shared test utilities (`mock-api.ts`):** Extracted in Story 1.5 review, reduced duplication across 4 test files
- **TDD discipline maintained throughout** — red-green-refactor lifecycle followed consistently
- **Test count growth:** 58 → 117 tests across the epic, 100% coverage on shared package

## Challenges

- **Tooling friction in foundation stories:**
  - Drizzle Kit CJS bundler incompatibility with `.js` ESM imports from `@todo-app/shared` (Story 1.2) — workaround: bypass shared imports in schema file
  - Tailwind v4 CSS variables not wiring to utility classes (`bg-primary`, `bg-muted` were no-ops) — root fix: `@theme inline` directive in globals.css (Story 1.3, caught manually by dvd)
  - ES module live binding bug: `export const = app` captured `undefined` permanently in integration test setup (Story 1.2, CRITICAL)

- **Story 1.2 cognitive overload:** Bundled infrastructure setup (Drizzle, migrations, triggers) with feature implementation (full CRUD routes). Led to 3 CRITICAL issues caught in review:
  1. `export const fastifyApp = app` captured `undefined` — needed `export let` for ES module live binding
  2. `Type.String({ default: false })` — boolean default on string schema
  3. Dead `errorCodes` import suppressed with `void` hack

- **Shallow test assertions in early stories:** Story 1.2 mocks only checked `db.select` was called, not verifying actual query parameters. Refactored in review.

- **Architecture spec inaccuracy:** "burst 20" documented for `@fastify/rate-limit` but the library doesn't support burst. Corrected in Story 1.2 review.

- **No visual integration testing:** Visual bugs (Tailwind CSS var issue, delete button visibility, ErrorMessage layout) only caught manually by dvd or during code review. No automated visual smoke testing in place.

## Key Insights

1. **Foundation investment pays off** — tooling friction in Stories 1.1-1.2 enabled smooth sailing in 1.3-1.5
2. **Visual integration testing is a gap** — automated tests verify DOM structure but can't catch visual correctness issues (CSS vars rendering as transparent, layout misalignment)
3. **Reusable abstractions compound velocity** — `useTodoStates`, `TodoRepository`, `mock-api.ts` all paid for themselves within the same epic
4. **Story complexity should be managed** — bundling infrastructure setup with feature work creates cognitive overload and review risk
5. **Review quality improved over the epic** — Stories 1.4-1.5 had mostly MEDIUM/LOW findings vs. 3 CRITICALs in Story 1.2

## Patterns Established

1. Named exports only — zero `export default` (ESLint enforced, framework config exceptions)
2. kebab-case files, PascalCase components, camelCase hooks
3. Repository pattern for backend data access
4. Optimistic UI: no rollback on create errors (keep visible for retry), yes rollback on toggle/delete errors
5. Per-todo UI state tracking via `useTodoStates` hook
6. Error classification via `classifyError()` — permanent (400/404/422) vs transient (everything else)
7. `ApiFetchError extends Error implements ApiError` with `status: number`
8. Co-located tests (`.test.ts` next to source)
9. Commit convention: `feat(impl):` prefix
